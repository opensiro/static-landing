The organization
toolchain.

Two halves of one fixed boundary. foundry elicits where knowledge comes from. vsmforge compiles what the organization is. Either side is replaceable; the boundary is not.

foundry

Alpha · Layer −1

The discovery layer. Describe an organization from any source — interviews, repos, tickets, docs.

foundry is the human entry point for describing organizations. It is a skill set, not a binary — a curated collection of discovery channels that obtain raw organizational knowledge and route it downward into the compiler.

It elicits intent; it never creates the org model directly. Every channel — a founder interview, a GitHub import, a consulting engagement — feeds the same canonical layer below, because none of them touches the model.

What it is not

Not an agent framework. Not a workflow designer. Not a runtime configurator. It prepares organizational intent for compilation — nothing more.

Discovery channels

Twelve named sources: bootstrap, startup, company, refactor, consulting, audit, migration, github, repository, jira, confluence, well-known.

vsmforge

Alpha · PyPI

The compiler. Layer 6 identity anchor — seed and verify viable-system environments.

vsmforge is the organizational compiler SDK — think of it as LLVM for organizations. It consumes the structured knowledge foundry hands off and runs the compiler passes: semantic validation, inference, VSM generation, runtime preparation.

The developer never hand-designs System 1–5. The system derives them from a semantic organization model. Layers 6→2 are declarative — what the organization is. Layer 1 is the only executable layer and is itself a VSM.

The layer model

Descends 6→1. Each layer is verified for correctness before the next is formed. The handoff between the two formation phases — executive and operative — is the only seam.

Compiler surface

Commands: identity (regulate Layer 6), scaffold, handoff, verify, serve/monitor, custom, doctor.
